# SEO 优化工作流

> 基于 GSC 数据的落地页 SEO 优化标准流程

## 触发条件

当用户提供以下两样东西时自动启动：
1. 目标页面的 GSC 搜索词导出文件（xlsx/csv）
2. 对应的工具 JSON 配置文件路径

## 标准流程

每一步必须按顺序执行，不能跳过：

### ① GSC 数据分析
- 解析 xlsx/csv，按展现量倒序排列
- 输出：总查询词数、总展现、总点击、CTR、平均排名
- 输出：排名区间分布（1-3 / 4-10 / 11-20 / 21-50 / 51-100）
- 输出 Top 50 查询词表格
- 输出有点击的词（>=2）和排名 4-20 的机会词

### ② 词群分析
- 按用户意图将查询词分组（如 format/validate/convert 各自一组）
- 每组标注：展现量、核心词（展现最大者）、搜索意图类型
- 判断哪些可以融合进当前页面、哪些需要独立建新页面
- 选取核心词（展现量最大的词）作为竞品分析锚点

### ③ 竞品对比
- 用核心词抓取 Google 排名前 3-5 的页面
- 对比：Title 格式、功能差距、内容深度（FAQ/教程）、信任信号
- 输出结论框架：竞品做得好的（你的及格线）vs 竞品没做到的（你的机会点）

### ④ 读取当前 SEO 配置 + 判断是否要改
- 读取工具 JSON 的 meta.title、meta.description、keywords
- **先判断是否需要改**：
  - CTR > 5% + 核心词排首页 → 直接告知"不需要改"
  - 否则 → 进入优化方案设计
- 多语言对比：如果同时有 EN/ZH 数据，分别决策

#### ④-bis 高流量页面保护检查（必须执行）

**在任何优化方案设计之前，必须先完成此检查：**

1. **读取 GSC 数据，计算页面流量基线**：
   - 总点击、总展现、CTR、平均排名
   - 识别页面已排名的核心词群（即流量来源词群）

2. **判断目标词群是否与现有流量词群一致**：
   - **一致**（如同为 "formatter" 词群的变体）→ 可以在现有页面优化
   - **不一致**（如页面核心词是 "formatter"，但要覆盖 "validator"）→ 触发独立页面决策

3. **独立页面决策矩阵**：

   | 条件 | 推荐方案 | 理由 |
   |------|---------|------|
   | 页面月点击 ≥ 500，目标词群与现有不同 | **新建独立页面** | 大改高流量页面风险高，可能动摇现有排名 |
   | 页面月点击 ≥ 500，目标词群是现有词群的同义扩展 | **微调现有页面** | 风险低，自然融入即可 |
   | 页面月点击 < 500，目标词群与现有不同 | **可选：新建或改现有** | 流量基数小，风险可控 |
   | 页面月点击 < 500，目标词群与现有相同 | **优化现有页面** | 直接提升 |

4. **输出决策结论**：在报告 ④ 步骤必须明确写出：
   - 当前页面流量基线数据
   - 目标词群与现有词群的关系
   - 最终决策（优化现有 / 新建独立页面）+ 理由

### ⑤ 具体优化方案
按优先级：
1. **Title** — 核心词前置、融入兄弟词、加 CTR 修饰词（Free/No Upload/数字）
2. **Meta Description** — 前半句覆盖核心词+兄弟词、中间强调差异化、自然融入场景词
3. **Keywords** — 基于 GSC 兄弟词扩充
4. **FAQ** — 检查问题措辞是否匹配 GSC 高频查询词
5. **Article** — 检查是否覆盖核心词群的用户场景

### ⑤-bis 关键词-内容覆盖验证（必须执行）
优化方案写入 JSON 后，**必须运行覆盖检查**，确保每个 keyword 都自然融入了页面内容。

**修复规则**：
- 缺失的关键词必须融入**自然语言**中，不能硬塞
- 优先融入位置：FAQ 问题标题 > FAQ 答案 > Article 正文 > Description
- 同义词/变体（如 "json" vs "JSON"）不算覆盖，必须精确匹配子串
- 覆盖率目标：**100%**（每个 keyword 至少出现在一个内容区域中）

### ⑥ 预期效果估算
- 根据当前展现量 × 目标排名 CTR 公式估算点击
- 标注"排名提升需等域名权重积累"（如果当前排名 >20）

### ⑦ 执行
- 确认后直接更新工具 JSON（en/zh 同步）
- git commit + push
- 提交信息格式：`seo(页面名): Title前置核心词+Keywords扩充`

## 重要规则

1. **多语言同步更新** — en / zh
2. **直接写回 JSON** — 不需要用户手动改文件
3. **FAQ/Article 也要检查** — 不只改 Title/Description
4. **先分析再决定** — CTR 已经好的页面不要过度优化
5. **记录预期** — 每次优化后标注是否需要等排名积累
6. **关键词 100% 覆盖** — 每个 keyword 必须自然融入至少一个内容区域（⑤-bis 步骤）
7. **高流量页面保护** — 月点击 ≥ 500 的页面，如果目标词群与现有流量词群不同，必须优先考虑新建独立页面，而非大改现有页面（④-bis 步骤）
