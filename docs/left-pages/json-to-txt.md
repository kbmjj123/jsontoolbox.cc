## 推荐功能范围

第一版建议提供 5 种输出模式。

### 1. Flatten to Text

输入：

```json
{
  "user": {
    "name": "Alice",
    "address": {
      "city": "Shanghai"
    }
  }
}
```

输出：

```text
user.name: Alice
user.address.city: Shanghai
```

这是当前 SERP 中最有差异化的模式。Cleanor、BuildQuill、ToolNimba 等页面都强调 dot notation 和 leaf values。 [buildquill](https://www.buildquill.com/tools/json-to-text)

### 2. Key-Value

输出：

```text
name: Alice
age: 30
active: true
```

适合文档、邮件、报告和人工检查。

### 3. Values Only

输出：

```text
Alice
30
true
```

适合：

- 提取 JSON 中的文本。
- 复制到表格或文本列表。
- 从 API response 中快速获取内容。

### 4. Keys / Paths Only

输出：

```text
user.name
user.address.city
```

适合：

- API 字段清单。
- JSONPath 参考。
- 文档生成。
- 调试字段结构。

### 5. JSON Lines

输出：

```text
{"id":1,"name":"Alice"}
{"id":2,"name":"Bob"}
```

这个模式必须明确叫：

```text
JSON Lines
```

不要叫“JSON to one line”，因为后者可能被理解为 minified JSON。

## 实际 SERP 分析

当前 SERP 可以分成三个明显方向。

### 1. 纯文本提取

iToolHub、FileConverts、Online Tools 和 ToolWard 主要将 JSON 的结构符号去掉，输出文本值或 key-value 行。 [itoolhub](https://itoolhub.com/en/json-to-text)

这类页面满足：

- 把 API response 转成可读文本。
- 去掉 `{}`、`[]`、引号和逗号。
- 复制到邮件、文档和报告。
- 快速阅读嵌套数据。

### 2. Flatten / dot notation

BuildQuill、Cleanor 和 ToolNimba 更强调扁平化路径：

```text
user.name: Alice
address.city: Shanghai
items[0].id: 1
```

其中 Cleanor 明确强调：

- 每个 leaf value 一行。
- object 使用 dot notation。
- array 使用 bracket index。
- 输出适合搜索和 diff。
- 本地浏览器处理。 [buildquill](https://www.buildquill.com/tools/json-to-text)

这是最适合 JsonToolBox 差异化的方向，因为它能和 JSONPath Tester、API 调试、JSON Schema 和 JSON Editor 形成清晰的内部工具链。

### 3. 多模式转换

BetterBugs 提供：

- JSON Lines。
- Keys/paths。
- Values。
- key=value。
- path:value。

 [betterbugs](https://www.betterbugs.io/development-tools/json-to-text)

因此，页面不应只做单一输出。推荐至少提供：

```text
Flatten paths
Key-value
Values only
Keys only
JSON Lines
```

ASCII tree 可以作为第二阶段功能。

## 功能边界

### 不要把 JSON to Text 写成 JSON.stringify

`JSON to text` 可能有两种完全不同的用户需求：

#### 需求 A：提取纯文本

```json
{
  "name": "Alice"
}
```

输出：

```text
name: Alice
```

#### 需求 B：序列化对象

```js
JSON.stringify({ name: "Alice" })
```

输出：

```text
{"name":"Alice"}
```

当前页面应服务需求 A。需求 B 应由后续独立的：

```text
/tools/json-stringify
```

承接。

### 不要承诺可逆转换

Flatten 输出：

```text
user.name: Alice
```

可能无法还原以下信息：

- 原始 key 是否包含点号。
- 数组边界。
- 数值与字符串类型。
- 空对象和空数组。
- null 与字符串 `"null"` 的区别。
- 对象属性顺序。

因此页面必须明确：

> Plain-text output is not a lossless replacement for JSON.
