`.json` 文件就是纯文本，所以没有「必须装某个 JSON 软件」这回事。区别只在于用什么打开才看得清、能不能立刻知道它是坏的、改完还能不能存回一个合法的文件。

想马上看内容，把文件拖进 [JSON 编辑器](/tools/format/json-editor) 就行：语法着色、边输边校验、2 或 4 空格格式化、改完复制或下载。它在你浏览器里跑，文件不上传。

![JSON 编辑器：粘贴压缩成一行的 JSON，格式化后按层级展开](/blog/screenshots/zh/how-to-open-json-file/01-json-editor-formatted.webp)

*粘贴一段压缩的接口响应后，左侧自动排好缩进，右侧树形视图逐个标出值的类型（时间戳还会单独识别）；底部是缩进、压缩、验证和导出操作。*

后面的内容是各种具体环境：Windows、macOS、Linux、浏览器、VS Code、手机、打不开时怎么排查，以及改完怎么存回 `.json`。

## .json 文件里装的是什么

一个 JSON 文件就是一个文本文件，扩展名是 `.json`，里面装一个 JSON 值——通常是对象或者数组：

```json
{
  "name": "Ada",
  "active": true,
  "roles": ["admin", "editor"]
}
```

因为是文本，从记事本到 VS Code 到浏览器都能打开它。编辑器加上语法着色和校验，浏览器一般只显示原始文本或者自带一个查看器。格式本身的规则见 [JSON 是什么？](/blog/what-is-json)。

## Windows 上怎么打开

**记事本**，自带的那一个：

1. 右键文件 → **打开方式** → **记事本**。也可以先开记事本再 **文件 → 打开**，这时候要把文件类型改成**所有文件（\*.\*）**，否则列表里看不到 `.json`。
2. 打开就是纯文本。没有着色、没有校验，压缩过的文件是一整行。

**Notepad++**：免费，有 JSON 语法着色，也有 JSON viewer 插件。右键 → **打开方式** 里选它。

**VS Code**：常干活的话用它：

1. 右键文件 → **Open with Code**。
2. 有高亮、实时校验、折叠，一键格式化。

想把 VS Code 设成 `.json` 的默认打开程序：右键 `.json` 文件 → **打开方式** → **选择其他应用** → 选 **Visual Studio Code** → 勾上**始终使用此应用打开 .json 文件**。

双击打不开、或者打开的是 WPS / 浏览器，说明默认程序被别的软件关联走了，按上面这段改回来就行。

## macOS 上怎么打开

**文本编辑**（自带的那个）能开，但有个坑：

1. 右键文件 → **打开方式** → **文本编辑**。
2. 如果看到字体和排版控件，说明它按富文本打开了，按 **Shift + Cmd + T**（**格式 → 制作纯文本**）切回纯文本。
3. 只看看没问题；要改的话注意保存那一步。

**VS Code** 更合适：右键 → **打开方式** → **Visual Studio Code**，或者打开 VS Code 用 **文件 → 打开**。

设成默认：右键文件 → **显示简介** → **打开方式** → 选 **Visual Studio Code** → **全部更改…**。

## Linux 上怎么打开

任何文本编辑器都行：

```bash
nano data.json     # 终端编辑器
gedit data.json    # GNOME 默认编辑器
code data.json     # 装了 VS Code 的话
```

桌面文件管理器里也能右键 → **打开方式** 选编辑器。只想瞄一眼就不用开编辑器：`cat data.json` 直接打印，`jq . data.json` 会解析并排版后打印——`jq` 报错就说明这个 JSON 本身是坏的。

## 在浏览器里查看

本地文件可以直接拖到浏览器窗口里，或者按 **Ctrl + O**（Windows / Linux）、**Cmd + O**（macOS）选择文件。

| 浏览器 | 看到什么 |
|---|---|
| **Firefox** | 自带 JSON 查看器：语法着色、节点可折叠、还有过滤框 |
| **Chrome** | 原始文本。想要着色和折叠得装扩展 |
| **Edge** | 同 Chrome，默认原始文本，扩展能补上树形视图 |

这条路适合只读检查，不适合编辑：浏览器不会把改动写回文件，压缩成一行的文件在哪个浏览器里都读不了。

调试接口时顺手能用的一个东西：Chrome DevTools 的 **Network** 面板里点开某条返回 JSON 的请求，Response 子面板左下角有个 `{}` 按钮，点一下就地排版（Chrome 93 起有这个功能）。它只对当前页面抓到的网络响应有效，本地文件用不上。

## 想用 Excel 或 WPS 表格打开

这是国内问得最多的一条：双击 `.json`，选了 Excel / WPS 打开，得到一大坨或者一堆乱码。

表格软件不认 JSON 这种嵌套结构。硬打开有两条路，都不好用：直接打开会被当成文本塞进一列；走 Power Query 之类的导入，嵌套对象和数组还是得你自己一层层展开。就算展平了，还有个更隐蔽的坑——订单号、身份证号这种长数字会被 Excel 转成科学计数法，最后几位直接变成 0。

要看表格，先把 JSON 转成表格文件：[JSON 转 CSV](/tools/convert/json-to-csv) 出 CSV（Excel 和 WPS 都能直接开），[JSON 转 Excel](/tools/convert/json-to-excel) 直接出 `.xlsx`。嵌套字段怎么变成列名、数组怎么处理，转换时会有选项。

## 用 VS Code 打开、格式化、校验

1. **打开**：右键 → **Open with Code**，或者 **文件 → 打开文件**。
2. **格式化**：**Shift + Alt + F**（Windows / Linux）或 **Shift + Option + F**（macOS）。也可以右键 → **格式化文档**。
3. **校验**：语法错误红色波浪线标出来，鼠标悬停看消息。缺逗号、括号不匹配、引号写错，边写边报。
4. **折叠**：对象和数组左边的折叠箭头，用来收起大文件里不看的段落。
5. **保存**：**Ctrl + S** / **Cmd + S**，`.json` 扩展名保留。

两点提醒。VS Code 的校验只查语法，不查你的数据是不是符合预期的结构。另外 VS Code 在某些配置文件里接受注释，是因为它按 JSONC 读——这不代表它们是合法 JSON，细节见 [JSON 里能写注释吗？](/blog/json-comments)。

## 中文输入法写坏的 JSON

手写 JSON 时有个很常见的失败：文件内容看着对，解析器一律拒绝。多半是全角标点混进去了。

```jsonc
{
  “name”: “Ada”，
  "age"：30
}
```

三处问题：中文引号 `“”`、中文逗号 `，`、中文冒号 `：`。JSON 只认 ASCII 的 `"`、`,`、`:`。`JSON.parse` 会在第一个全角字符那儿报 `Unexpected token`，位置指到那个全角字符上——在编辑器里它和普通标点长得几乎一样，肉眼很难发现。

写配置文件时把输入法切到英文状态，或者写完之后用编辑器格式化一下：格式失败的位置基本就是全角字符的位置。

## 手机上怎么看

手机没有内置的 JSON 查看器，三条路：

- **文本编辑器 App**：应用商店里随便一个都能把 `.json` 当文本打开。看一眼够用，压缩过的基本没法看。
- **专门的 JSON 查看器 App**：Android 和 iOS 都有，会排版、能折叠节点。
- **手机浏览器**：打开 [JSON 编辑器](/tools/format/json-editor)，粘贴文件内容，或者浏览器支持的话直接选文件。不用装东西，还能改，在手机上通常是最顺的一条路。

在微信、钉钉里收到 `.json`，一般得先「用其他应用打开」或者直接保存到本地再处理；文件名可能在传输过程中被加了个 `.txt` 后缀，先确认一下扩展名。

手机上改大文件不现实，不管用什么 App。真要改，传到电脑上。

## 文件打不开时怎么排查

| 现象 | 大概原因 | 怎么办 |
|---|---|---|
| 打开是乱码，或者夹着 `\u0000` 一样的空白 | 编码不对：UTF-16，或者是二进制文件改了扩展名 | 重新导出成 UTF-8；用 `file data.json` 确认真实类型 |
| 第一个字符就把解析搞挂 | 文件开头有 UTF-8 BOM | 存成不带 BOM 的 UTF-8 |
| 中文全变成 `ç¼–ç` 这类 | 存成了 ANSI / GBK，不是 UTF-8 | 用 VS Code 打开，改成 UTF-8 编码重新保存 |
| 文件名其实是 `data.json.txt` | 记事本存成了文本文档，Windows 又隐藏了已知扩展名 | 重命名去掉 `.txt`，在资源管理器里打开「显示扩展名」 |
| 打开有字体、有排版 | 它是富文本（RTF / DOCX），不是 JSON | 找真正的源文件，或者把文本复制到纯文本编辑器里 |
| 文件 0 字节或者明显被截断 | 下载 / 导出中断 | 重新下载，和源文件的大小对一下 |
| 提示权限不足 / 文件被占用 | 别的程序正占着，或者没有读权限 | 关掉那个程序，检查文件权限 |
| 能打开，但每个解析器都拒绝 | JSON 本身非法：尾随逗号、注释、单引号 | 先校验，再用 [JSON 修复](/tools/format/json-repair) 处理 |
| 编辑器卡死或者拒绝打开 | 文件太大，不适合在浏览器里编辑 | 用 [大文件 JSON 查看器](/tools/view/large-json-viewer) |
| 双击打开是 Excel 的一列 | 用表格软件打开了 JSON | 转成 [CSV](/tools/convert/json-to-csv) 或 [Excel](/tools/convert/json-to-excel) 再看 |

报错信息看不懂的话，[JSON 解析失败：10 个常见 API 错误与排查方法](/blog/json-parse-error-debug) 把常见报错一条条拆开讲。

## 改完怎么存回 .json

内容改对只完成一半，保存时扩展名和编码都得对。

**记事本**：

1. **文件 → 另存为**。
2. **保存类型**选**所有文件（\*.\*）**，否则存出来是 `data.json.txt`。
3. 文件名写全：`data.json`。
4. **编码**选 **UTF-8**，然后保存。（Windows 10 1903 之前的记事本默认存 ANSI，中文会变乱码；1903 之后默认就是 UTF-8 不带 BOM。）

**VS Code**：**Ctrl + S** / **Cmd + S**。扩展名和编码都保留，改坏了立刻有波浪线提示。

**在线编辑器**：点**下载**，存成 `.json`。替换原文件前先留一份备份。

## 什么时候用在线编辑器，什么时候用本地

**用在线编辑器的情况**：

- 现在就要看一个文件，不想装东西。
- 这台机器装不了软件：公司电脑、Chromebook、手机。
- 只想格式化、校验、搜一下、下载，不想动原文件。
- 数据里有密钥、客户信息这类不想传到别人服务器上的内容。[JSON 编辑器](/tools/format/json-editor) 的解析、校验、格式化、压缩都在浏览器里完成，页面不上传你的 JSON。

它能给的比「看一眼」多一些：语法着色、实时校验、2 或 4 空格格式化、压缩、树形视图里每个节点能复制 JSONPath、按键名 / 值 / 路径 / JSONPath 子集搜索、直接在树里改、对象数组能切成表格并导出 CSV、结果可复制可下载。

**用本地编辑器的情况**：

- 这几个文件你要反复改，或者它们在 Git 仓库里。
- 需要离线可用。
- 文件大到浏览器里编辑不动。

**分界线是文件大小。** JSON 编辑器面向 5 MB 以内的日常文档（`LARGE_FILE_MAX_BYTES`，`app/composables/useLargeFile.ts:60`）；超过这个尺寸，内容会被交给 [大文件 JSON 查看器](/tools/view/large-json-viewer)。后者只读：打开大 JSON 和 NDJSON，只渲染可见的那几行，搜索放在 Web Worker 里跑所以页面不卡，能按行号跳转、导出命中的行。它不编辑也不重新排版——要改的话在本地处理，或者把文件拆小。

## FAQ

### 能用记事本打开 JSON 文件吗？

能。右键 → **打开方式** → **记事本**，或者先开记事本用 **文件 → 打开**，文件类型选**所有文件（\*.\*）**。记事本只显示原始文本，没有着色和校验。从记事本保存时记得选「所有文件」和 UTF-8，否则会得到 `data.json.txt`。

### Mac 上怎么打开 .json 文件？

右键 → **打开方式** → **文本编辑**（如果按富文本打开了，按 **Shift + Cmd + T** 转纯文本），或者用 VS Code，改内容时它更好用。想把 VS Code 设成所有 JSON 文件的默认程序：**显示简介** → **打开方式** → **Visual Studio Code** → **全部更改…**。

### 能用 Chrome 打开 JSON 文件吗？

能。把文件拖到 Chrome 窗口上，或者按 **Ctrl + O** / **Cmd + O**。Chrome 显示原始文本，想要着色和折叠得装扩展。Firefox 自带 JSON 查看器。调试接口时可以用 DevTools Network 面板的 `{}` 按钮给响应排版。

### 为什么我用 Excel 打开 JSON 是一坨乱码？

表格软件不理解 JSON 的嵌套结构，要么整段塞进一个单元格，要么按编码猜错了。中文变乱码通常是文件存成了 GBK / ANSI 而 Excel 按别的编码读。先看编码，再看你到底想要什么：只想读内容就用文本编辑器或在线编辑器，想要表格就先转成 [CSV](/tools/convert/json-to-csv) 或 [Excel](/tools/convert/json-to-excel)。

### JSON 文件怎么格式化？

VS Code 里按 **Shift + Alt + F**（Windows / Linux）或 **Shift + Option + F**（macOS）。浏览器里粘进 [JSON 编辑器](/tools/format/json-editor)，选 2 空格、4 空格或压缩，然后复制或下载。格式化要求 JSON 本身合法——有语法错误先修语法。

### 我的 JSON 文件为什么打不开？

常见的就这几种：文件其实叫 `data.json.txt`、存成了富文本或带了 BOM、下载的文件不完整或者是二进制、文件太大超出了工具能处理的范围。先看文件名和编码，再校验内容——上面的排查表里每一行都对应一个具体动作。

### 能在网上编辑 JSON 文件吗？

能。在 [JSON 编辑器](/tools/format/json-editor) 里粘贴或打开文件，改值、增删字段、调整数组顺序，校验后下载。别加注释，标准 JSON 没有注释语法，见 [JSON 里能写注释吗？](/blog/json-comments)。

### 把 JSON 传到在线工具里安全吗？

取决于那个工具。不少在线查看器是把文件上传到它们服务器的，对含密钥、令牌、客户数据的配置文件来说是实打实的风险，粘贴前先看它的隐私说明。本站的工具在浏览器里处理数据、不上传——但不管用什么在线工具，都不该把生产环境的凭据和机密数据贴进去。

### .jsonl / NDJSON 文件怎么打开？

同样是纯文本，任何编辑器都能开。但它是每行一个独立的 JSON 值，所以整体拿去格式化会被拒绝。用 [大文件 JSON 查看器](/tools/view/large-json-viewer)（支持 NDJSON），或者用 [JSONL 转 JSON](/tools/convert/jsonl-to-json) 转成数组再看。
